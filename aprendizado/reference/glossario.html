Glossário de recuperação e autenticação

Termos exatos para falar do fluxo de senha no Klok. Use estas definições em qualquer conversa sobre o código.

Segurança

Token de recuperação

Valor aleatório de 32 bytes gerado no servidor e enviado por email. Prova que quem clicou tem acesso à caixa de entrada do dono da conta.

Evitar: código de 6 dígitos, senha provisória fixa.

Hash sha256

Função que converte o token em um texto único e irreversível. O banco guarda só o hash, nunca o token original.

Evitar: chamar de criptografia, pois criptografia permite voltar ao valor original.

Uso único e expiração

O token vale por 30 minutos e pode ser trocado por uma nova senha apenas uma vez. Ao usar, todos os tokens do usuário são invalidados.

Evitar: token sem prazo ou reutilizável.

Resposta genérica

O mesmo texto de sucesso é devolvido exista ou não o email, para não revelar contas cadastradas no sistema.

Evitar: mensagens como "email enviado", pois denunciam contas existentes.

Salt

Dado aleatório adicionado à senha antes do hash, para que senhas iguais gerem hashes diferentes. Usado em criarHashSenha no db.js.

Evitar: hash de senha sem salt.

Navegação entre email e app

Deep link

URL com scheme próprio do app, como klok://redefinir-senha?token=..., que abre o app instalado no celular.

Evitar: achar que é um link https comum.

Página de confirmação

Página HTML curta servida pelo back-end que, com um toque de botão do usuário, dispara o klok://. Contorna o bloqueio do Gmail e do navegador a schemes customizados.

Evitar: botão invisível ou redirecionamento automático, que o navegador bloqueia.

Sessão

Conjunto token JWT guardado no celular que mantém o usuário logado. Limpar a sessão obriga novo login.

Evitar: chamar sessão de cookie, que é tecnologia de navegador.

Deslogamento

Ação de apagar a sessão local após a redefinição, para o usuário entrar com a senha nova.

Evitar: manter o usuário conectado com o token antigo.
